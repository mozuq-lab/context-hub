# 方針（POLICY）の検証手順

Vault直下のAGENTS.md「3. 方針（POLICY）」の詳細です。方針が関係しうる作業をするときに、POLICY.md の内容を継続的な指示として使ってよいかを、ContextHub CLI（`ctx`）で確かめる手順を説明します。CLIの導入・設定変更や方針の再生成は、自動では行いません。

## 1. CLIがあるか確認する

| 環境 | コマンド |
|---|---|
| macOS・Linux | `command -v ctx` |
| Windows（PowerShell） | `Get-Command ctx -ErrorAction SilentlyContinue` |
| Windows（コマンドプロンプト） | `where ctx` |

見つかった場合は、続けて次の2点を確認します。

- `node --version` が24以上であること。
- `ctx --help` の表示が AI Context Hub のCLIで、全体オプションに `--vault`、コマンドに `policies` があること。

見つからない、Nodeが使えない・24未満、CLIを識別できない、のいずれかなら、「3. CLIがない場合」へ進みます。このCLIは、保存用の `submit-input.mjs` とは別のツールです。

## 2. 方針を読み取る

`policies` の出力にはVaultのパスが含まれないので、既定設定の保存先に頼らず、常に `--vault` でこのVaultの絶対パスを明示します。

```sh
ctx --vault "<このVaultの絶対パス>" policies
ctx --vault "<このVaultの絶対パス>" policies --project <既存ID>
```

共通の方針だけなら1行目、対象プロジェクトが明確なら2行目を使います（2行目は共通とプロジェクトの両方を返します）。成功したら、出力全文を読みます。AGENTS.mdの継続的な指示として適用できるのは、ここで検証できた有効方針だけです。

読み取りはVaultを変更しないので、同じコマンドを再実行しても安全です。ただし、エラーが続くときに繰り返し実行し続けることはしません。

## 3. CLIがない場合

POLICY.md を未検証の資料として読み、継続的な指示としては自動で従いません。

- 今回の作業に関係しそうな記載、または関係するか判断できない記載があれば、ID・内容・未検証であることを示し、今回その内容で進めるかを本人に確認する。POLICY.md が欠損・読取不能の場合も確認する。返答を待つ間も、独立した作業は続けてよい。
- 関係する記載がなければ、確認を挟まずに通常の作業を続ける。ただし「有効方針なし」「方針に適合することを確認済み」とは断定しない。「有効な方針はありません」という表示だけで、有効方針がないとも断定しない。

本人が今回同意した内容は今回限りの指示です。それによって、方針や同期状態が検証済みになるわけではありません。

## 4. 検証エラーが出た場合

CLIは動いたが検証に失敗した場合は、方針に関わる判断・変更を止め、エラー文をそのまま本人に示して、下表の対処を案内します。「3. CLIがない場合」の手順で迂回しません。対処はMini側の操作や同期の完了なので、AIは実行しません。

| エラー表示 | 意味 | 本人への案内 |
|---|---|---|
| 方針は未初期化・未同期です。Miniで集約し同期してください | Miniでまだ方針が集約されていないか、この端末に同期が届いていない | 同期の完了を待つか、Miniでの集約を依頼する |
| 方針の正本とmanifestが一致しません。同期または集約の回復が必要です | 正本（KNW・承認記録）と集約の版がずれている | 同期の完了を待って再確認する。続く場合はMiniでの集約の回復を依頼する |
| 方針の集約が未同期・変更されています／方針の集約情報が不正です | POLICY.md などの集約ファイルが同期途中か、手で変更された | 同期の完了を待って再確認する。続く場合はMiniでの再集約を依頼する |
| 方針の版が取得中に変わりました | 読み取り中に同期で更新が届いた | 少し待ってから1回だけ再実行してよい |
| 対象プロジェクトの方針が未同期・未登録です | `--project` のIDがMiniで未登録か、まだ同期されていない | IDが正しいか確認する。正しければ同期の完了を待つ |
| 受付ファイルの容量または種類が不正です／受付ファイルの容量が上限を超えています | 読取対象のmanifestや正本などが上限（1MiB）を超えたか、通常ファイルではない。方針の読取でも、共通の読取処理により「受付ファイル」と表示される | 本人に対象ファイルの容量・種類の確認を依頼する。整理や復旧が必要ならMini側での対応を依頼する |
| その他 | — | エラー文をそのまま示す |

`方針manifestの容量が上限を超えています`は、Miniでの集約・書き込み時のエラー表示です。`ctx policies`の読取でmanifestが1MiBを超えた場合は、上表の容量・種類のエラーになります。共通・各プロジェクトの方針本文には別途32KiBの上限があります。方針本文の上限に関するエラーでは、不要な方針の適用停止や置換での整理を本人に依頼します。

## 5. 自動注入hookとの関係

ここで説明したのは、AIが手動で方針を読み取る手順です。全作業への方針自動注入は別途導入・動作確認が必要で、AGENTS.mdの配置だけでは有効になりません。導入済みのhookや端末共通の指示で全文の検証が必須とされている場合は、その条件を守り、この手動向けの省略・代替手順で検証の失敗を迂回しません。
