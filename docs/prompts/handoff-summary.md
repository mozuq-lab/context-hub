# 作業終了時の要約プロンプト

次を、作業したAIへそのまま渡してください。

```text
この作業を次回再開するため、短いMarkdown要約を作成してください。会話全文・コード全文・ツールログは不要です。秘密情報や認証情報を含めないでください。

基本見出しは「## 現在地」「## 次の一手」「## 未解決」の3つです。各箇条書きの先頭に [確認済み] [提案] [未確認] のいずれかを付けてください。

[確認済み] はこのセッションで根拠を示せる事項だけです。実行した検証はコマンドと実際の結果を書き、実機未確認・他AIの自己報告・利用者からの伝聞を独立検証済みにしないでください。
「次の一手」の[確認済み]は合意済み作業だけに使い、新しい案は[提案]にしてください。未決定の期限、優先度、プロジェクト、完了状態を作らないでください。

出典同士の不一致、古い状態、判断待ちは「未解決」に残します。不明な事項は不明としてください。
本文末尾に、ツール名・プロジェクトID・作業日時（タイムゾーン付き）・元セッション参照先を付けてください。不明な値は「不明」、プロジェクト未指定なら「未指定」、元会話を参照できない場合は「元会話は参照不可」と書いてください。
メタ情報は「---」で区切り、その直前に空行を1行入れてください。次の行に「ツール: <ツール名> / プロジェクト: <IDまたは未指定> / 作業日時: <タイムゾーン付き日時または不明> / 元セッション: <参照先または元会話は参照不可>」の形式で書いてください。
```

メタ情報の例です。値は実際の情報に置き換えます。

```text

---
ツール: claude-code / プロジェクト: context-hub / 作業日時: 2026-11-01T19:30:00+09:00 / 元セッション: 元会話は参照不可
```

## 端末からInputへ保存する場合

別Mac等のAIは、利用者が保存を依頼した場合にだけ [submit-input.mjsの保存手順](file-input.md)とVault直下のAGENTS.mdに従います。`--kind work-summary`を指定します。プロジェクトは既存の `project.md`の `id`が明確な場合だけ `--project`へ渡し、未承認の候補は使いません。

オプション・出典名・終了コードと結果の照合は[file-input.md](file-input.md)、保存してよい条件はVault直下のAGENTS.md「5. 保存」に従います。末尾のメタ情報は上の例の形式にします。保存ツールが付ける `occurred_at`は保存実行時刻なので、過去の作業日時と元セッション参照先は本文末尾に残します。下記のMini管理CLIのオプションを保存ツールへ付けません。

保存依頼がない場合は本文の作成・保存の提案までに留め、勝手に保存しません。

## Mini上の管理CLIを使う場合

以下はMini管理者向けの別コマンドの説明です。`submit-input.mjs`へ付けるオプションではありません。通常の端末保存を行うAIは、これらの管理操作を実行しません。

Mini本体のCLIでの取り込みでは `--kind work-summary`を指定します。プロジェクトは本人が別途 `project add`で登録した既存IDだけを `--project`で指定します。作業日時を `--occurred-at`、AI名を `--tool`、元セッション参照先を `--session`へ渡すと構造化メタデータに保持できます。Node 24以上と、対象・影響を確認した管理操作の権限が必要です。
