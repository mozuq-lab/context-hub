# 構成とデータ

ContextHubはCapture、Organize、Writer、Retrieveを分けます。coreはOpenClawから独立し、CLIとMockLlmで中核を検証できます。

| 部分 | 役割 |
|---|---|
| Capture | InputのREQやDiscordの入力を受け、原文・日時・出典・IDを保存 |
| Organize | 原文と既存プロジェクト定義をモデルへ渡し、分類・要約・関連候補のJSONを取得 |
| Writer | スキーマ、パス、ロック、ハッシュを検証し、許可された生成物と処理記録を更新 |
| Retrieve | 検索、プロジェクト再開、文字数制限付きのコンテキスト出力 |

## Vault

```text
Input/                         端末が追加する不変の受付ファイル
00_inbox/                      正式原文・訂正原文
10_projects/<id>/project.md     プロジェクト定義
10_projects/<id>/NOW.md         現在地・次の一手・未解決の生成ビュー
20_ideas/                      AI整理済みアイデア
30_knowledge/                  共通へ採用した正式知識・方針
10_projects/<id>/knowledge/     対象projectへ採用した正式知識・方針
POLICY.md                      共通の有効方針（派生集約）
10_projects/<id>/POLICY.md      対象projectの有効方針（派生集約）
90_system/                     受領・処理・訂正解釈・候補・承認・競合の記録
HOME.md                        受領と整理状況への入口
_ContextHub/                   共有する入力ツールとテンプレート
```

ロック、ログ、個人設定、認証情報、バックアップはVaultの外へ置きます。端末別のObsidian設定は標準では同期しません。

## 原文と生成物

原文は作成後に変更しません。同じイベントの再送は重複保存を防ぎ、別イベントの同じ文章は別の入力として保持します。REQは端末保存の記録、正式なIN IDはMiniでの原文保存の記録です。

モデルは保存先やIDを決めません。結果はスキーマで検証し、出典・日時・未検証表示を維持します。分類不能のunclassifiedは正常な結果であり、処理成功と内容の確認済みは別です。

NOWは根拠から決定的に組み立てます。古い入力で新しい状態を巻き戻さず、AI自己報告、提案、未確認、訂正未反映を分けます。自動領域の手動変更は無断上書きせず競合へ退避し、手動領域は保持します。

## 訂正と承認

訂正は元原文を残した新しい入力です。最新の訂正チェーンと整理済みの解釈を区別し、未反映なら旧要約を最新の確定事項として扱いません。

プロジェクトや恒久知識を確定する操作には、人が確認した候補とハッシュ等を結び付けます。モデルの本文に「承認済み」とあっても承認になりません。同期Vaultへ任意書き込みできるローカルプログラムを隔離する本人認証の仕組みではありません。

## 実行と同期

端末はInputへ新規ファイルを追加し、Miniが正式原文と生成物を書きます。Mini内のWriterは共通ロックで排他しますが、このロックは他端末やSyncthingの変更を排他しません。整理は別の整理用ロックで実行全体を排他し、Writerロックは対象の選択と結果の確定の短い区間だけ取得します。モデルの応答を待つ間もメモの保存・受付・承認は進みます。待機中に訂正が届いた入力やプロジェクト定義が変わった入力は書き込まず、次回の整理で処理します。待機中に原文が書き換えられた場合は整合性違反として停止します。共有端末とローカルプロセスを信頼し、正式原文や処理記録の直接編集を避ける運用が前提です。

cycleのモデル不要受付とAI処理枠は別です。`cycle --limit 2`は整理・承認回復・再関連付けを合計2件まで処理します。形式不正時の再問い合わせがあるため、件数は厳密な料金上限ではありません。
