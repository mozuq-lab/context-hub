# 採用した知識・方針を使う

候補を採用するときは、内容・理由・元メモと採用先を確認します。元メモにプロジェクトが指定されていれば引き継ぎ、AIの推定は推定と表示します。複数・不明なら採用先を選び、未定なら保留できます。却下・保留に採用先は不要です。全ての作業に共通とする場合は、本人が共通を明示選択します。

| 種類 | 採用後の扱い |
|---|---|
| 判断・方針 / 好み（decision/preference） | 共通または対象プロジェクトの有効方針としてAIへ渡す |
| 参考知識（knowledge） | 必要なときに検索・参照する |

projectの正式記録はContextHub内の`10_projects/<id>/knowledge/`、共通の正式記録は`30_knowledge/`へ保存します。開発リポジトリへ本文を複製しません。Vault直下と各projectの`POLICY.md`は有効方針の読取用集約で、Miniが再生成します。直接編集しません。

採用履歴から「適用停止」を依頼すると、KNWとAPRを残したまま本人の停止記録を追加します。停止・置換済みの内容は有効方針から外れます。再び使うときは新しい候補を確認して採用します。元メモの訂正だけでは、採用済み方針を自動変更・停止しません。

Obsidianは[QuickAdd](../examples/quickadd/README.md)の採用・却下・適用停止、Flutterは候補詳細と採用履歴で操作できます。端末の依頼保存と、同期後のMini受領・反映を区別してください。

## 読取とAI接続

```sh
ctx policies --project example-project
ctx policies --cwd /absolute/path/worktree --json
```

読取は実モデルを呼ばず、Vaultを変更しません。共通と対象projectの有効方針だけを、全文・正本パス・承認ID・同期版hashとともに返します。未初期化・未同期・変更を空の方針と扱いません。新しい採用や停止記録だけが先着したときも、古いmanifestで読み続けません。共通/各projectはそれぞれ32KiB以内です。

contextコピーも同じ方針を先に含めます。上限は関連メモを削って調整し、必須方針だけで収まらなければコピーを止めます。自動整理にも同じ方針を渡し、出力schemaや承認権限を変更する指示には変換しません。

全作業への接続には、[AI接続の設定準備](../examples/policy-connectors/README.md)を使います。準備ツールは既存設定を保持した差分と復元手順だけを作ります。実設定の反映とhook trust、実セッションへの全文到達は導入時の別確認です。Codexのcloud orchestration等、ローカルcommand hookが非対応の方式もあります。接続用のAGENTS.mdを置いただけで自動注入済みとはしません。

未指定scopeの既存記録は表示・検索できますが、自動で共通方針にしません。適用先を確認し、新候補として採用します。AIは採用・停止要求を代作しません。
