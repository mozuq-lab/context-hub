# 週次の統合（今週の気づき）

既定では無効です。有効にすると、たまったメモをモデルが週に1回まとめて読み直し、メモ1件を読むだけでは分からないことを「今週の気づき」としてHOMEとふりかえりの先頭に出します。

整理（`organize`）はメモを1件ずつ分類・要約します。週次の統合は、複数のメモを見比べて次の5種類を返します。どれもAI生成・未検証で、根拠のメモへのリンクを付けます。

| 欄 | 内容 |
|---|---|
| つながり | 別々のメモ同士のつながり（続き、具体化、矛盾、同じ問い）。根拠は2件以上 |
| 考えの変化 | 同じ話題について、時間とともに考えや関心がどう動いたか。根拠は2件以上 |
| 止まっている意図 | 「したい」「調べたい」と書いたまま、続きが見当たらないもの。最初の一歩を添える |
| 次の一手の提案 | 複数のメモを踏まえると、今やる価値がある次の一手 |
| 問い | 答えると考えが進む、本人への問い |

各欄は3件までです。足せることがなければ、その欄は出しません。プロジェクトの作成・帰属・完了・期日は変えません。

## 有効にする

設定ファイルに`synthesis`を足します。書かなかった項目は既定値になります。

```json
{
  "synthesis": {
    "enabled": true
  }
}
```

| 項目 | 既定 | 意味 |
|---|---|---|
| `enabled` | `false` | 週次の統合を使うか |
| `intervalDays` | `7` | 自動で実行する間隔（1〜90日） |
| `thinking` | `medium` | 思考の深さ（`off`・`minimal`・`low`・`medium`・`high`）。整理の`organize.llm.thinking`とは別に決めます |
| `timeoutSec` | `150` | 1回の実行全体の時間の上限（1〜600秒）。形式の作り直しと、分けた呼び出しを含みます |
| `maxFocusMemos` | `30` | 1回の呼び出しに全文で渡すメモの上限（1〜100件） |
| `maxContextMemos` | `100` | 1行にして渡すメモの上限（0〜500件） |
| `maxCalls` | `1` | 全文で渡すメモを分ける呼び出しの上限（1〜4回） |

モデルの接続先（`provider`・`model`・`executable`・`agent`）は整理と同じ`organize.llm`を使います。`cycle --thinking`は整理だけに効き、統合の思考の深さは`synthesis.thinking`で決まります。

## いつ実行されるか

`cycle`が整理の後に判定し、実行した回は同じ`cycle`のふりかえりとHOMEに結果を出します。`cycle --dry-run`では実行しません。

- 最後の実行（失敗を含む）から`intervalDays`が過ぎていれば実行します。有効にして最初の`cycle`が初回です。
- 前回の成功の後に届いたメモがなければ、モデルを呼ばず、前回の気づきを出したままにします。新しいメモが届いた後の`cycle`で実行します。
- 失敗した回の後は、次の間隔まで自動では実行しません。モデルの障害で毎回の呼び出しを重ねないためです。HOMEの「失敗と競合」に理由とやり直し方を示します。
- モデルを呼ぶ前に、実行を始めたことを記録します。ジョブの制限時間や再起動で途中で止められた実行も1回として数え、次の`cycle`で呼び直しません。
- 読めない実行の記録があると、前回の実行時刻が分からないので自動では実行しません。HOMEと`doctor`に記録の場所を示します。

実行の種類は3つです。

| 種類 | 条件 | 全文で渡すメモ |
|---|---|---|
| 初回（`first`） | 成功した実行がまだない | 新しい順に上限まで |
| 週次（`weekly`） | 前回の成功の後に届いたメモが3件以上 | 前回の成功の後に届いたメモ（新しい順に上限まで） |
| 見直し（`quiet`） | 前回の成功の後に届いたメモが3件未満 | 新しく届いたメモと、以前のメモを新しい順に上限まで |

「届いた」はMiniが受け取った日時（`received_at`）で判定します。発生日時が古いメモを後から同期した場合も、新しいメモとして扱います。前回の成功の後に訂正が届いたメモも、新しいメモとして扱います（訂正の整理を待つ間は渡しません）。訂正が前回の成功より前に届いていても、その整理が前回の成功の後に済んだメモ（前回は整理を待つため渡さなかったメモ）は、新しいメモとして扱います。見直しの回は、以前のメモを今の視点で見直す問いと、止まっている意図を中心にします。

## モデルへ渡す内容

入力が増えても、1回に渡す量は上限で決まります。

- 全文で渡すメモ（`maxFocusMemos`件まで）: 300文字以下のメモは本人の原文、それより長いメモは整理の要約（整理前なら冒頭の300文字）で渡します。訂正のあるメモは、訂正を重ねた整理の要約で渡します。訂正の整理を待つメモは、古い解釈を渡さないよう外します。
- 1行にして渡すメモ（`maxContextMemos`件まで）: 全文で渡さないメモを新しい順に選び、80文字以下なら本人の言葉、長ければ要約の先頭80文字で渡します。以前のメモとのつながりを見つけるための材料です。
- それ以外のメモは渡しません。件数を実行の記録に残します。
- メモごとに、書いた日・入力の種類・AIの分類・結び付いているプロジェクト名・新しく届いたメモかを添えます。[問いへの答え](#反応と答え)のメモには、答えている問いを添えます。ほかに、登録済みのプロジェクトの名前と状態（50件まで）、前回示した項目（同じ内容を繰り返させないため。本人の反応と、答えがあるかを添えます）、今日の日付を渡します。
- [秘密情報らしい文字列](operations.md#秘密情報らしい文字列を伏せる)は、切り詰める前と送る直前に伏せ字にします。
- プロンプトが100KiBを超える場合は、1行にして渡す件数、次に全文で渡す件数を半分ずつ減らします。

`synthesize --dry-run`は、モデルを呼ばず、何も書き込まずに、渡す件数と送るプロンプトの大きさ（バイト）を示します。無効のままでも確かめられます。

```sh
node packages/core/dist/cli.js --config "<設定ファイル>" synthesize --dry-run
```

## 応答の検証

モデルの応答はコードが検証し、通った項目だけを採ります。落とした項目は、欄と理由だけを実行の記録に残します（本文は残しません）。

- 渡していないメモを根拠に挙げた項目、根拠のない項目、本文が空の項目は落とします。
- 根拠が20件を超える項目は落とします。
- つながりと考えの変化は、根拠が2件に満たなければ落とします。
- 週次の回は、新しく届いたメモを根拠に含まないつながり・考えの変化・次の一手の提案・問いを落とします（止まっている意図は、以前のメモだけでも採ります）。
- 前回示した項目と同じ欄・同じ根拠の組み合わせは、繰り返しとして落とします。根拠のメモにその後訂正が届いていれば、繰り返しとして扱いません。
- 本文が240文字を超える項目は落とします。最初の一歩が160文字を超える場合は、最初の一歩だけを外します。
- 各欄は3件までで、超えた分は落とします。
- 本文と最初の一歩から、制御文字と表示の向きを変える文字を除きます。
- 応答をJSONとして読めないとき、または応答の項目が参照の誤り（渡したメモの参照名と一致しない）・形の崩れ・空の本文ですべて落ちたときは、理由を添えて1回だけ作り直させます。2回続けば、その回を失敗として記録します。

## 表示

- HOMEの先頭と、ふりかえり（REVIEW.md）の「概要」の前に「今週の気づき（AI生成・未検証）」を出します。項目ごとに根拠のメモへのリンクを付け、気づきを作った後に訂正が届いたメモには「（訂正あり）」を付けます。
- 間隔を過ぎても新しい結果がないときは、何日前の結果かを添えます。足せる気づきがなかった回の後は、欄を出しません。前回と同じ項目しか返らず、繰り返しとして落とした回の後は、前回までの気づきを出したままにします。
- 同じ内容を`90_system/insights.json`（派生）に書き、アプリの対応版がホームの先頭に表示します。最後に成功した実行の項目（`latest`。項目ごとに本人の反応`reaction`と答えのメモ`answers`を含みます）、最後の実行の状態（`last_attempt`）、次に自動で実行する時刻（`next_due_at`）、読めない記録の件数（`record_problems`）を含みます。内容が変わったときだけ書き直します。
- モデルが書いた本文は、見出し・引用・入れ子の箇条書き・リンク・HTMLとして読まれないよう無害化して1行で載せます。

## 反応と答え

アプリのホームで、気づきの項目ごとに反応を付け、問いに答えられます。どちらも次の週次の統合で使い、件数をふりかえりに出します。

- **反応**: 「役に立った」（`useful`）か「的外れ」（`off-target`）を付けます。付けた反応をもう一度押すと外します（`none`）。アプリは受付ファイル（`operation: insight-reaction`、`run_id`・`item_key`・`reaction`・`confirmed: true`、本文は空）で依頼し、`cycle`の受付で`90_system/insight-reactions/IRX-<ID>.json`に記録します。記録は書き換えず、同じ項目への反応は、本人が押した日時（依頼の`occurred_at`）が最後のものを有効にします。実行の記録にない実行・項目への反応は、理由（`insight-missing`）を付けて受け付けません。
- **答え**: 問いなどの項目に答えると、答えはふつうのメモとして保存されます。どの気づきへの答えかは、メモの`meta`（`capture_mode: insight-answer`、`insight_run`、`insight_key`、`insight_question`）に残します。問いの本文も残すので、メモだけを読んでも何への答えかが分かります。整理は、ほかのメモと同じく本文だけで行います。
- 一覧（`insights.json`）とアプリには、項目ごとに有効な反応と答えのメモを示します。反応と答えの反映は、受付の後のHOMEの作り直し（`cycle`）で行います。
- 次の週次の統合では、前回示した項目に本人の反応と答えがあるかを添え、答えのメモには答えている問いを添えて渡します。的外れと言われた項目と同じ方向の項目を出さないこと、答えた項目を聞き直さないこと、答えを踏まえて次に進む項目を考えることを依頼します（プロンプトの版2）。
- ふりかえり（REVIEW.md）の「今週の気づきへの反応」に、項目を出した直近4回の実行ごとに、項目数と、役に立った・的外れ・答えた項目の数を出します。HOMEには出しません。テーマの抽出などへ進むか（段階3）を判断する材料です。
- 読めない反応の記録は飛ばして一覧を作り、`doctor`で場所を示します。

## 実行の記録

実行ごとに`90_system/synthesis/SYN-<ID>.json`を残します。モデルを呼ぶ前に開始を記録し、終わったら同じファイルを結果で置き換えます。それ以外では書き換えません。

- `status`: `ok`（項目あり）・`empty`（応答は正しいが足せる項目なし）・`failed`（失敗）
- `mode`・`period`: 実行の種類と、新しいメモとして扱った期間
- `llm`: 接続先の種類、モデル名（実行側の報告。なければ設定の値）、思考の深さ、プロンプトの版（反応と答えを渡す版は2）
- `counts`: 新しく届いたメモ、全文で渡したメモ、1行にして渡したメモ、渡さなかったメモの件数
- `calls`: 呼び出しごとの所要時間（ミリ秒。形式の作り直しを含む）、最も長くかかった1回の試行の時間、試行回数、送ったプロンプトの大きさ、失敗の種類
- `items`: 採った項目（欄、本文、最初の一歩、根拠のメモ）
- `dropped`: 落とした項目の欄と理由
- `error`: 失敗の種類。`invalid-output`（応答の形式が不正）・`timeout`（時間切れ）・`prompt-too-large`（送る内容が大きすぎる）・`llm-error`（モデルの呼び出しに失敗）・`interrupted`（途中で止まった）

運用ログには、件数と所要時間だけを残します。

## 時間と費用

- モデルを呼ぶのは、間隔ごとに1回です。形式が崩れたときの作り直し1回と、`maxCalls`を2以上にしたときの分割を除きます。
- OpenClawのGatewayが応答を待つ時間は120秒で、設定では変えられません。1回の試行に90秒以上かかると、HOMEの「失敗と競合」に注意を出します。その場合は`maxFocusMemos`・`maxContextMemos`を減らすか、`thinking`を下げてください。
- `timeoutSec`は実行全体の上限です。残りが30秒に満たないときは、作り直しや次の呼び出しを始めません。`cycle`のジョブに制限時間を付けている場合は、整理に掛かる時間とこの秒数の合計が収まるようにしてください。制限時間で止めるときにSIGTERMを送る実行環境ではロックを解放して終わりますが、SIGKILLで止められるとロックが残り、`ctx doctor --unlock`で外すまで次の`cycle`が止まります。
- `maxCalls`を2以上にすると、全文で渡すメモを時間順に、件数をなるべくそろえて複数回の呼び出しへ分けます（1回あたり`maxFocusMemos`件まで。全文で渡せる上限は`maxFocusMemos × maxCalls`件）。各回は、自分の分を全文で、ほかの回の分を1行で受け取ります。結果は欄ごとに交互に採り、同じ根拠の重なりと上限を超えた分を落とします。一部の呼び出しが失敗しても、成功した分は出します。呼び出しは順に行うので、`timeoutSec`とジョブの制限時間も合わせて延ばしてください。
- 送る内容は設定済みのモデルで処理されます。扱いは[情報と費用](operations.md#情報と費用)と同じです。

## 手動で実行する

```sh
node packages/core/dist/cli.js --config "<設定ファイル>" synthesize
node packages/core/dist/cli.js --config "<設定ファイル>" synthesize --force
node packages/core/dist/cli.js --config "<設定ファイル>" synthesize --thinking low
node packages/core/dist/cli.js --config "<設定ファイル>" cycle --retry-failed
```

- `synthesize`は`cycle`と同じ判定で実行し、実行した場合はふりかえりとHOMEを作り直します。無効のときは断ります。
- `--force`は、間隔・新しい入力の有無・読めない記録にかかわらず1回実行します。
- `--thinking`は、その回だけ思考の深さを変えます。
- `cycle --retry-failed`は、最後の実行が失敗していれば間隔を待たずにやり直します。失敗が3回続いた後は、次の間隔を待つか`synthesize --force`を使います。

## 無効に戻す

`enabled`を`false`に戻すと、次の`cycle`でHOMEとふりかえりから欄を外し、`90_system/insights.json`を空にします。実行の記録（`90_system/synthesis/`）は消しません。一度も有効にしていないVaultには、何も作りません。

## 現在の制限

- 話題の束（テーマ）の抽出は、まだありません。
- 次の統合に渡す反応と答えの有無は、前回示した項目の分だけです。それより前の実行の項目への反応は、ふりかえりの件数にだけ使います。
- 同じ欄・同じ根拠の繰り返しは、直前に項目を出した回とだけ比べます。それより前の項目が、もう一度出ることがあります。
- 自動テストは偽のモデルとMockLlmで行っています。実モデルの応答の質と所要時間は、導入環境で`synthesize --dry-run`と最初の実行の記録から確かめてください。
