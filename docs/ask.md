# 記録に聞く

「前にこの件はどう決めたか」「あの不具合はどう直したか」のような問いに、Vaultの記録（メモ・作業要約。訂正があれば最新の訂正）だけを根拠に答えます。答えの文ごとに根拠の記録とその引用が付き、元のメモへたどれます。

答えはAI生成・未検証です。メモにはなりません（アプリで「メモとして残す」を押したときだけ、答えを本人のメモとして送ります）。

## 使い方

CLIでは次のように聞きます。整理と同じモデル（`organize.llm`）を1回呼びます。

```sh
node packages/core/dist/cli.js --config "<設定ファイル>" ask "バックアップは結局どういう方式にしたんだっけ"
node packages/core/dist/cli.js --config "<設定ファイル>" ask "配布方法" --project context-hub
node packages/core/dist/cli.js --config "<設定ファイル>" ask "配布方法" --dry-run   # 渡す記録だけを表示（モデルは呼ばない）
```

[Mac・Androidアプリ](https://github.com/mozuq-lab/context-hub-flutter-client)では、メニューの「記録に聞く」から問いを送ります。アプリは問いを受付ファイル（`operation: ask`、本文が問い、`project`は任意）としてInputへ保存し、本体は受付で「答え待ち」として`90_system/answers/ASK-*.json`に記録します。答えは次の`cycle`で作り、同期でアプリへ戻ります。受付ではモデルを呼びません。

## 答えの作り方

1. 問いに近い記録を、コードが選びます（AIは使いません）。日本語の問いは空白で区切られないため、問いと記録を2文字ずつの並びで比べ、多くの記録に出る並びと、ひらがなだけの並び（言い回しの一部であることが多い）は軽く数えます。最も近い記録の4割に満たない記録は渡しません。`--project`を付けると、そのプロジェクトに帰属・関連する記録だけから選びます（統合済みのプロジェクトは統合先）。
2. 選んだ記録（既定で20件まで、`ask.maxSources`）を[伏せ字](operations.md#秘密情報らしい文字列を伏せる)にし、1件1500文字まで（長い記録は問いの語が集まる部分）を渡します。問いに近い記録がなければモデルを呼ばず、「見つかりませんでした」と返します。
3. モデルには、渡した記録だけを根拠に、文ごとに根拠の記録（1〜3件）と本文からそのまま写した引用を付けて答えるよう頼みます。記録どうしが食い違うときは日時を添えて両方を示させ、答えられないときは「見当たらない」と返させます。本文は引用データとして渡し、中の指示には従わせません。
4. コードが応答を確かめます。渡していない記録を指す根拠、モデルへ渡した本文にそのまま含まれない引用（空白と改行の違いは同じとみなす）、句読点や短い語だけの引用は捨て、根拠が残らない文は落とします。残った文がなければ答えを出さず、根拠の候補だけを返します。形式の崩れた応答は1回だけ作り直させます。

答えの状態は、`answered`（答えあり）、`not-found`（記録に見当たらない）、`unsupported`（根拠を確かめられる文がなかった）、`no-sources`（問いに近い記録がない）、`failed`（答えを作れなかった）、`pending`（答え待ち）です。`failed`の理由（`error`）は、呼び出しの失敗のほか、答える前に選んだプロジェクトがなくなった`project-missing`（モデルは呼びません）があります。

モデルが返した引用は、渡した記録の本文にそのまま含まれるものだけを残します。長い本文を切り出したときに前後へ付ける省いた印（…）は本文ではないため、印をまたぐ引用は根拠にしません。

## 呼び出しの上限

アプリからの問いは、`cycle`が1回に`ask.maxPerCycle`件（既定3件）まで答えます。直近24時間に試した回数が`ask.dailyLimit`（既定30回）に達したら、答え待ちのまま次の機会に回します。試す前に回数を記録し、途中で止められた（再起動など）問いは3回で失敗として閉じます。答えた記録は30日で片付けます（問いの受付ファイルと受領記録は残ります）。

設定の`ask.enabled`を`false`にすると、CLIとアプリの問いを受け付けません（受付ファイルは理由付きで断り、再試行しません）。アプリは`90_system/intake-features.json`の`ask.enabled`を見て「記録に聞く」を出さなくなります。無効にする前に受け付けた問いは答え待ちのまま残り、有効に戻すと答えます（アプリは、無効の間はそのことを問いの状態に示します）。

```json
"ask": { "enabled": true, "maxSources": 20, "timeoutSec": 90, "maxPerCycle": 3, "dailyLimit": 30 }
```

## 制限

- 根拠になるのはメモと作業要約だけです。アイデア・知識・NOWの本文は直接は渡しません（それらの元になったメモから答えます）。
- 引用の一致は、モデルが本文を写したことを確かめるだけです。答えの文が引用の内容を正しく言い換えているかまでは確かめません。根拠の引用と元のメモで確かめてください。
- 問いと記録の言葉が大きく違うと、近い記録を選べないことがあります。`--dry-run`で渡す記録を確かめ、言葉を変えて聞き直してください。
- OpenClaw（Discord）のスラッシュコマンドには足していません。OpenClawのツールの中から同じOpenClawのモデルを呼び直すことになり、待ち時間と呼び出しの重なりを確かめていないためです。
